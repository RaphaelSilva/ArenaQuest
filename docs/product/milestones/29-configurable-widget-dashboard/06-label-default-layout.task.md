# Task 06 — Backend: Label default layout in profile, preflight and Worker var (Phase 2)

**Status:** 📝 Open
**Milestone:** [29 — Configurable Widget Dashboard](./milestone.md)
**RFC:** [RFC 0008](../../RFCs/0008-user-dashboard-with-topic-recommendations-and-badge-achievem.md)
**Team:** Backend API
**Depends On:** [Task 03](./03-layout-driven-dashboard-aggregate.task.md)

## Summary

Inserts the **label tier** between the code default and everything else. A label profile
(`config/labels/<label>.jsonc`) may declare `dashboard.defaultLayout`. The deploy CLI validates it
**before any command** with a new TypeScript check script that uses the shared strict parser and
also checks the serialised size; an invalid layout aborts the deploy, naming the failing path. A
valid one is passed to the Worker as `DASHBOARD_DEFAULT_LAYOUT` on `wrangler deploy` and on
`wrangler preview`; a profile without the key passes no var. In the Worker, the layout resolver reads
the var: absent → code default; present but invalid → code default plus one error log line (never
a `500`). `GET /v1/admin/dashboard/label-default` (`admin`, `content_creator`) returns the deployed
label default, or the code default with `source: 'code'`, for the backoffice preview in Task 08.
`layoutSource.kind` becomes `label` when this tier applies, and a student copy made from it records
`based_on = 'label'`.

## Technical Constraints

- **Scope guardrail:** changes restricted to:
  - `scripts/deploy/core.mjs` (profile `dashboard` key, fail-closed preflight step, size check) and
    `scripts/deploy/core.test.mjs`.
  - `scripts/cloudflare/deploy.mjs` (map the step to the check script; append
    `--var DASHBOARD_DEFAULT_LAYOUT:<json>` to the Worker deploy and preview commands) and
    `scripts/cloudflare/deploy.test.mjs`.
  - `apps/api/scripts/check-dashboard-layout.ts` (new).
  - `apps/api/src/core/dashboard/**` (label tier + env parsing), the new admin route file
    `apps/api/src/routes/admin/dashboard-layouts.ts` (this task adds only the label-default read)
    mounted from `apps/api/src/routes/admin/index.ts`, its controller, `container.ts` wiring.
  - `apps/api/worker-configuration.d.ts` (regenerated by `make cf-typegen`), `apps/api/openapi.json`,
    `apps/api/src/openapi/components/**` and `apps/api/test/**`.
  - `config/labels/*.jsonc` — **no profile is required to change**; adding a key to one profile is
    optional and only as a documented example.
- **One validator.** The check script imports the shared module; `core.mjs` does not re-implement
  the schema.
- **Secrets untouched.** The layout is a plain var, never a secret; nothing is logged beyond the
  failing path.
- **Preview parity.** A Workers Preview gets the same var as the Worker it previews.

## Scope
